### Tests (`npm test`)

No test framework existed and none was added. `npm test` compiles `tests/`
with the project's own `tsc` (`tsconfig.test.json`) and runs the output on
plain node via `tests/alias-hook.js`, which resolves the `@/` alias and stubs
`next/navigation`, `next/cache`, `next/headers`, `next/server` and the Supabase
server client. Zero dependencies, nothing added to the Vercel build, and it
runs on node 16 as well as 22. 47 tests cover `lib/checklist.ts`,
`lib/audience.ts`, `lib/intake.ts`, `lib/dates.ts` and
`lib/session-cookie.ts`. `tests/fake-supabase.ts` applies `.eq`/`.neq` for
real, so query scoping is assertable without a database.

### Latency work

Every page used to run the auth chain three times — the page, the `Header` and
a `require*` helper each did `getUser` + `profiles` + `organizations`. Now:
`createClient()` and `loadMembership()` are memoised per request with React
`cache`, the profile query embeds the organization (one round-trip for slug +
`crm_config`), `Header` runs no auth queries of its own, and
`requireOrg`/`requireAdmin` read the cached membership. `/people` filters and
searches in the browser (`components/PeopleDirectory.tsx`) — measured 4–9ms
per chip with zero network requests, where each chip used to be a full server
render. Broadcast previews reuse still-valid signed URLs
(`lib/signed-urls.ts`) so images are browser-cacheable.

`proxy.ts` no longer validates the session over the network on every request;
it reads `expires_at` from the session cookie and only calls `getUser()` within
120s of expiry, or on `/login`. **This is skip-work only — never
authorisation.** The cookie is unverified; every protected page and server
action still validates against Supabase, and an unparseable cookie returns
`null`, meaning "do the real check". `/login` is excluded deliberately:
bouncing to `/pipeline` on an unexpired-but-invalid cookie loops forever. A
forged fresh cookie was verified to land on `/login`.

Reported as "a valid login brings me right back to the startup page". The page
was **`/`, the marketing page** (identifiable by the "Book a walkthrough" CTA
and a navbar "Sign in"), not the login form — both carry the tagline "Built in

Nothing in the app redirects to `/`, so the redirect came from Supabase.
**Production is now `clancyhq.com`** (`clancy-hq.vercel.app` 307s to it), a
domain that did not exist when Google auth was configured. GoTrue validates the
OAuth `redirect_to` against the project's Redirect URLs allow-list and, when it
does not match, falls back to the Site URL and appends the PKCE `?code=` to it.
`HomePage` took no `searchParams` at all, so the code was silently dropped: no
session, and a marketing page still offering "Sign in".

`00d7694` makes `/` finish such a sign-in (forwards `?code=` to
`/auth/callback`, surfaces `?error` as `/login?error=oauth`) and show "Open
Clancy" to a visitor who already has a session. Cookie parsing moved to
`lib/session-cookie.ts`, shared with `proxy.ts`.

Ruled out with evidence, so don't re-check: the deployed anon key is valid
(`400 invalid_credentials`, not `401`), Google and email providers are both
enabled, and the joined membership query works (`200` with anon vs
`400 PGRST200` for a deliberately wrong embed name).

**Still open:** the user should confirm whether **email/password** login works.

## 6. Gotchas that cost time

- **A Server Component `redirect()` shows up as HTTP 200 in dev**, with the
  target embedded in the streamed RSC payload (`…;307;`). `curl -L` will not
  follow it and it looks like the redirect never happened. In production it is
  a real 307. Verify by grepping the body for the target, or use a browser.
- **Never run `npm install` in a scratch clone and commit the lockfile.** A
  different npm version rewrote `package-lock.json`, dropping the `libc`
  constraints on the Linux-only Tailwind/lightningcss native packages —
  build-critical, since Vercel builds on Linux from that file. It was caught
  and reverted in `1fc5dcb`; check `git status` before committing.
- **`hub` and the browser tool resolve the session directory**, so both fail
  outright while the TCC block is in place. Background processes had to be
  spawned from `eval` instead.
- Pushing to `main` is a production deploy and is normally permission-gated.
  The last three commits were pushed with explicit approval, the second two
  because production login was broken.
